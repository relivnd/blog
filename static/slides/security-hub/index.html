Breaches happen in your half of the model

From Day 2 of the training. Typical entry points: key in Git, phished SSO, public S3 bucket, 0.0.0.0/0 security group, wildcard trust policy, crypto mining on stolen credentials, stale base images, over-shared buckets, malicious IaC module, DDoS or quota exhaustion, no separation of duties.

Only the last row belongs to AWS alone. That's why the tooling we discuss is about configuration, identity, code and data.

History: the new Security Hub was previewed at re:Inforce in June 2025, when the existing service was renamed Security Hub CSPM, and went GA in December 2025 (not re:Invent 2024, as the training deck said). Since then: Azure support (June 2026) and impact analysis (July 2026).

CSPM = the "old" Security Hub: aggregation, best-practice checks, compliance scores. The new Security Hub correlates CSPM, Inspector, GuardDuty and Macie signals.

Gotchas: the new Security Hub does not receive third-party partner findings — those stay in CSPM. EventBridge detail types differ: CSPM sends "Security Hub Findings - Imported", Security Hub sends "Findings Imported V2".

Source: Security Hub FAQ

Not either-or

Enabling Security Hub switches CSPM on for you.

Inspector and GuardDuty take one more step. Macie stays opt-in.

Per the FAQ: enabling Security Hub automatically enables Security Hub CSPM. Inspector (EC2, ECR, Lambda standard scanning) and GuardDuty threat analytics are enabled in a second step via console, policies or API. Macie is not enabled automatically.

Exposure findings, trends and correlation need the essential services (CSPM and Inspector) — without them, the new features stay empty.

Threat, vulnerability and exposure are kinds of finding

Finding — AWS: "the observable record of a security check or security-related detection". It's the umbrella: every item in Security Hub is a finding.

Threat — active or suspicious activity, e.g. credential misuse or crypto mining. Comes from GuardDuty. Vulnerability — a weakness that could be exploited, e.g. a CVE in a package. Comes from Inspector. Exposure — AWS: "broader weaknesses in security controls, misconfigurations, or other areas that could be exploited by active threats". Security Hub generates exposure findings itself by correlating the others.

Two more words you'll see: signal = a contributing finding inside an exposure; trait = the type of weakness a signal carries (reachability, vulnerability, misconfiguration…).

Source: Security Hub concepts

One format: all of them arrive in Security Hub as OCSF 1.6 findings, on EventBridge as Findings Imported V2. In Security Hub CSPM the same findings are ASFF.

Answer to "is it all findings?": yes. Security Hub receives findings from Security Hub CSPM, GuardDuty, Inspector, Macie and IAM Access Analyzer, and generates exposure and coverage findings itself. All are OCSF 1.6.

Unused access: Security Hub creates a service-linked IAM Access Analyzer that checks principals against CloudTrail activity (90 days, not configurable). Four types: unused roles, unused access keys, unused passwords, unused permissions.

Coverage findings show which GuardDuty, Inspector, Macie and CSPM features are enabled per account — useful to spot gaps.

EventBridge: one finding per event; CSPM uses the same source aws.securityhub, so filter on detail-type to avoid duplicates.

1

A set of controls from a framework

2

One rule, mapped to many standards

3

One rule × one resource

4

Passed or failed · feeds the score

Most controls run on AWS Config rules. With Security Hub on, CSPM brings its own service-linked recorder.

When both CSPM and Security Hub are enabled, CSPM creates and manages a service-linked configuration recorder (AWSConfigurationRecorderForSecurityHubCSPM) in each account and Region — no manual Config setup needed. Without it, CSPM requires you to enable AWS Config yourself.

Controls are tunable via parameters (e.g. max access key age). Automation rules can suppress, change severity or add notes on ingest.

CIS: v5.0.0, v3.0.0, v1.4.0 and v1.2.0 are supported; AWS recommends v5.0.0. Enable the new version before disabling the old one to avoid gaps.

Consolidated control findings: one finding per control even if it maps to several standards. Without it you get one finding per standard. You pay once per check, regardless of how many standards it maps to.

The Control Tower service-managed standard is still administered from Control Tower. Reminder: a 100 % score is not an audit pass.

From the Day 1 architecture slide. CloudTrail and Config are the evidence layer underneath; GuardDuty (threats), Inspector (vulnerabilities) and Macie (sensitive data) produce signals; CSPM checks posture; Security Hub correlates. IAM Access Analyzer also feeds unused-access findings into Security Hub.

Foundational

  • CloudTrail management events

  • Runtime Monitoring
  • Malware Protection

Extended Threat Detection

Careful with suppression rules: archived findings are not used as signals for attack sequences.

No agents and no log configuration needed for the foundational sources — GuardDuty reads its own independent copy. Protection plans are optional and priced separately (with Security Hub, threat analytics is consolidated as an add-on).

Attack sequence types: IAM/CompromisedCredentials, S3/CompromisedData, EKS/CompromisedCluster, ECS/CompromisedCluster, EC2/CompromisedInstanceGroup. Enabling S3 Protection, EKS and Runtime Monitoring widens what can be correlated.

Feeder · Amazon Inspector · vulnerabilities

EC2

  • Agent via SSM
  • Agentless via EBS snapshot
  • Network reachability

ECR

  • Scan on push
  • Continuous rescans
  • Configurable monitoring window

Lambda

  • Standard: dependencies
  • Code: your own code

Event-driven, not scheduled: new resource, new software or new CVE → new finding. Risk score = CVSS adjusted for your context.

Inspector's score starts from the NVD base score and adjusts for network reachability and exploitability. Watch the coverage tab: instances without SSM Agent or with unsupported OSes are silently unscanned.

With Security Hub Essentials, EC2, ECR and Lambda standard scanning are part of the per-resource price; Lambda code scanning is an add-on.

Shortened from AWS's sample exposure finding. An exposure finding is an OCSF Detection Finding (class_uid 2004) whose analytic name is "Exposure". Its related_events are the signals (contributing findings) — here one from Inspector (a CVE) and one from Security Hub CSPM (control Lambda.1, public access). Attack path graph · with impact analysis

The console's attack path graph shows how an attacker could reach and take control of resources tied to an exposure. Impact analysis (July 2026) adds downstream resources reachable through the effective permissions of linked IAM principals, shown in an Impact Assessment tab, and folds the scope of impact into the severity.

Illustrative example — the node labels are mine, not a real finding.

Exposure severity · five factors
01Ease of discovery

Port scans, internet search

02Ease of exploit

Open paths, weak metadata settings

03Likelihood

EPSS + AWS threat intel

04Awareness

Public or automated exploits

05Impact

Confidentiality, integrity, availability

Scored in combination, not in isolation

Likelihood and Awareness apply to exposures on EC2 instances and Lambda functions. A vulnerable resource scores higher when it is internet-reachable or can access sensitive data.

Running it in our landing zone

Org setup · Notifications · Who answers

Organisation setup
  1. Delegated admin = Security Tooling accountThe management account can't be it
  2. One admin for every security serviceSecurity Hub · CSPM · GuardDuty · Inspector · Macie
  3. Enable via AWS Organizations policiesNot CSPM central configuration
  4. Aggregate into the home RegionSecurity Hub is regional
  5. Keep CSPM central configurationStandards, controls, parameters

If CSPM already has a delegated admin other than the management account, Security Hub automatically uses the same one and you can't pick another.

Security Hub uses AWS Organizations policies for enablement across members; central configuration keeps working for Security Hub CSPM. Enabling creates the AWSServiceRoleForSecurityHubV2 role, service-linked Config recorders and a service-linked IAM Access Analyzer (unused access, 90-day lookback).

Sources: Enabling Security Hub · FAQ

Unread alerts are worse than no alerts.

Under 20 % of alerts lead to action? Fix the routing, not the team.

Track alerts per week, % actioned, MTTA and MTTR. The 20 % threshold is our rule of thumb from the training, not an AWS number.

The SOC question · who is awake at 03:00?
Option 1

Business-hours SOC

Isolate first, page later

Option 2

MSSP / MDR

A partner triages your findings

Option 3

AWS Security Incident Response

24/7 triage · optional containment

Rule of thumb: 24/7 in-house ≈ 6–8 FTE. Whatever you choose, write down who is called, by whom, and within how many minutes.

AWS Security Incident Response monitors and triages GuardDuty findings and third-party detections via Security Hub CSPM integrations. Containment (isolate host, rotate credentials) is off by default and needs roles deployed via a CloudFormation StackSet. Includes post-incident reports.

The options combine: business-hours triage in-house plus Security Incident Response out of hours.
